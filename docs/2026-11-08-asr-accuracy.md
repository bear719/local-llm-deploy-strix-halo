# 中文 ASR 识别准确率优化（flm NPU / whisper-v3:turbo）

日期：2026-11-08
对象：`http://127.0.0.1:8219/v1/audio/transcriptions`（flm v1.0.12，NPU）
产出：`tools/pyfix.py`（纠错器）、`tools/asr-bench.py`（基准）、docproxy 在线纠错

---

## 一、结论先行

**字符错误率（CER）从 23.06% 降到 4.11%，相对下降 82%。**

| 方案 | CER | 结论 |
|---|---:|---|
| flm NPU 原始输出 | 23.06% | 基线 |
| + 音频前处理（重采样/高通/归一化） | 25.34% | **负优化，否决** |
| + 语速减速 10% | 24.66% | **负优化，否决** |
| whisper.cpp(Vulkan) 同模型 | 22.37% | 与 NPU 持平，但更快 |
| flm + 确定性纠错（无 LLM） | 7.31% | 零额外延迟，可上线 |
| **flm + 完整纠错（模糊+整句判别）** | **4.11%** | 离线/批量用 |

**一句话结论**：flm 的 whisper 声学层几乎没有调优空间（参数不暴露、前处理有害），
但它的错误**高度规整**——90% 以上是同音字替换。字形选择是可以用词表+拼音
确定性地修的，这才是准确的正确入口。

## 二、为什么先建基准

改造前必须先能**量化**。真实录音没有 ground truth，改什么都只能"感觉好一点"。

本机 `edge-tts` 已被微软加校验（403），改用本地 **Breeze-TTS-2**（ggml Vulkan，
`$HOME/src/Breeze-TTS-2.cpp/build/breeze-cli`，模型 `breeze-tts-2-q8_0.gguf`）。
它走 carve-out VRAM，不占 30.47 GiB 的 GTT，与 35B 主服务不冲突。

测试集：**6 条消化内科病历文本 × 3 种音色 = 18 条**，共 146 字（归一化后）。
音色用 `--instruction` 模拟：

| 音色 | instruction |
|---|---|
| default | 中性普通话女声，常速 |
| male_fast | 中年男声，语速偏快，像打电话 |
| elder_low | 老年男声，低沉沙哑，语速慢 |

三种音色是必需的：中文 ASR 错误率与基频、语速强相关，单一音色上调出来的结论不可信。

### 一个必须修的 CER 计算坑

初版把「四十毫克」和 ASR 输出的「40毫克」算成 3 个字错，导致 CER 虚高 3 个百分点。
`norm()` 现在会把中文数字串转成阿拉伯数字（`四十→40`、`八十二→82`、`碳十三→碳13`），
再做全角转半角。**这一步不做，所有对比结论都会失真。**

## 三、五条路，四条否决

### 3.1 解码参数调优 —— 不可行

`flm serve --help` 全文没有任何 ASR 解码参数（无 temperature / beam / no_speech_threshold），
`/v1/audio/transcriptions` 只接受 `model` / `file` / `language` / `prompt`。
后两个已实测无效且有害（见 3.2）。

### 3.2 音频前处理 —— 负优化

| 处理 | CER | 相对基线 |
|---|---:|---:|
| 无 | 23.06% | — |
| 16k 重采样 + highpass 80Hz + dynaudnorm | 25.34% | **+9.9%** |
| atempo 0.9 减速 + 同上 | 24.66% | **+6.9%** |

原因推测：flm 内部已做重采样与归一化，外部再处理一遍等于二次失真；
whisper 的 log-mel 前端对增益变化本身不敏感。这与历史 whisper.cpp 路线
（`PhoneInbox/docs/asr-accuracy.md`）的结论一致：soxr / highpass 收益微弱。

### 3.3 换引擎 —— 不划算

同机 `whisper.cpp`（Vulkan 构建）+ `ggml-large-v3-turbo-q5_0.bin`，跑同样 18 条：

| 引擎 | 基线 CER | 基线耗时 | + 完整纠错 |
|---|---:|---:|---:|
| flm（NPU） | 23.06% | 24.5 s | **4.11%** |
| whisper.cpp（Vulkan） | 22.37% | 15.9 s | 8.68% |

基线几乎持平（差 3 个字），whisper.cpp 快 35%。**但加上纠错后反过来了**：
whisper.cpp 的错误里混着插入/漏字（如"主苏**少傅不**隐痛"多出三个字），
拼音纠错器修不了这类；flm 的错误更规整，基本全是同音替换，正好被词表吃掉。

结论：**保持 flm NPU 做 ASR + 文本侧纠错**。whisper.cpp 作为"更快但不那么可纠"的备选。

### 3.4 LLM 自由纠错 —— 已验证无效，不再试

历史结论（同一台机器，35B）已确认：自由生成式纠错是**生成任务**，模型倾向照抄原文，
强化 prompt 还会编造说话人。只有「是/否」判别这类**分类任务**才有效。
本次沿用这一约束：LLM 只做判别，绝不让它改写。

## 四、有效方案：四层流水线

顺序**不可颠倒**，每一步都为下一步准备条件。

```
ASR 原始文本
   ↓ ① 英文术语正则      Child-Pugh / EVL / EIS（拼音匹配对它无效）
   ↓ ② pass1 精确拼音    归一化拼音完全一致的确定性替换（零误伤）
   ↓ ③ 虚词规则          予/与/于/以（依赖 ② 已把「奥美拉座」改成「奥美拉唑」）
   ↓ ④ pass2 模糊匹配    ≥3 字术语 + 15 个高危 2 字词，必须过 LLM 整句判别
最终文本
```

### 4.1 拼音归一化（模糊音）

精确同音匹配救不了「套扎→套杂」（zh/z）、「胃肠镜→胃肠性」（ing/in）。所以在比对前
先把拼音按规则归一：

```
zh→z  ch→c  sh→s  iang→ian  uang→uan  ing→in  eng→en  ang→an
```

这样 `taozha` 和 `taoza` 落到同一个键。

### 4.2 三档匹配，风险分级

| 档 | 条件 | 是否需 LLM | 误伤风险 |
|---|---|---|---|
| 精确 | 归一化拼音完全相同 | 否 | 极低 |
| 长术语模糊 | 长度 ≥3 且相似度 ≥0.85 | **是** | 中 |
| 短词模糊 | 长度 2，**仅限 15 个白名单词** | **是** | 中 |

白名单：`既往 嗳气 阳性 阴性 患者 套扎 胃镜 肠镜 息肉 麻醉 活检 呕血 黑便 隐痛 腹胀`。
只对这份名单放开 2 字模糊，是因为全局放开会把「办理→伴理」这类正常词改坏。

### 4.3 两个把准确率从 7.3% 拉到 4.1% 的关键修正

**① 两遍法（先精确、后模糊）**

最初一次遍历同时做精确和模糊，结果「万反酸→伴反酸」被 LLM 否决（`p=1.000`，置信度拉满地
说"不改"）。原因是模糊候选送进判别时，上下文里还带着未纠错的错字（"主苏""饮痛"），
模型被干扰。改成 pass1 先把精确的全改完、句子干净了，再跑 pass2 模糊，立刻就过了。

**② 整句对比式判别**

原来给模型看「片段 + 12 字上下文」，现在改成：

```
原句：<整句>
改动后：<替换后的整句>
问题：把「X」改成「Y」，是否让这句话更通顺、更符合中文病历/门诊对话的表达？
```

同一批样本，片段式判否的「都门罗杆军→幽门螺杆菌」（相似度 0.933）在整句式下被正确放行。

**③ 处理顺序 bug**

虚词规则只对「与奥美拉唑」这类（正确写法）生效，但 ASR 输出的常是「于奥美拉**座**」——
错字导致规则不匹配。必须把虚词层放在精确纠错**之后**。

## 五、残余错误（4.11%，18 字）

| 类型 | 例 | 为何修不了 |
|---|---|---|
| 声母远距混淆 | 灌折→患者（guan/huan） | 2 字，相似度 0.857 但不在白名单 |
| 韵母跨类 | 盎起→嗳气（angqi/aiqi，0.6） | 低于模糊阈值，收紧会误伤 |
| 多字连错 | 寄王以心→既往乙型 | 拼音差太远 |
| 漏识 | 「B级」整段没输出 | 声学层丢失，文本侧无解 |
| 单字虚词 | 型→行、气→吸 | 单字不参与词表匹配 |

这些继续调参的边际收益很低，且容易过拟合到测试集。**建议停在 4.11%。**

## 六、生产接入

### 6.1 在线（docproxy 18090）

```bash
# start-docproxy.sh
NPU_ASR_FIX="${NPU_ASR_FIX-1}"      # 设为空串即关闭
```

`tools/docproxy.py` 在 `/v1/audio/*` 的非流式响应写回前，对 `text` 与
`segments[].text` 做**确定性层**（①②③）纠错。**故意不接 LLM**：代理是在线服务，
不能为一次转写额外引入 0.6 s/处的模型判别延迟。

任何异常（非 JSON、空体、数组、import 失败）都原样返回，绝不阻塞转写。

实测开销：1.43 s → 1.51 s（约 +80 ms，主要在首次建索引）。

### 6.2 离线（批量）

```bash
PY=$HOME/.workbuddy/binaries/python/envs/default/bin/python
$PY tools/pyfix.py "患者行未肠镜检查，与EVL套杂治疗。"
$PY tools/pyfix.py --file note.txt --llm --show      # 完整层
$PY tools/pyfix.py --dir transcripts/ --llm          # 批量干跑
$PY tools/pyfix.py --dir transcripts/ --llm --apply  # 写回（自动 .bak）
```

## 七、不适用清单（不要重试）

- ❌ 调 `language=zh` / `prompt` 词表：无效，且让耗时翻倍并诱发重复幻觉
- ❌ 音频重采样 / 高通 / dynaudnorm / 减速：**CER 反而升高**
- ❌ 全局放开 2 字模糊匹配：「素呼→术后」「示肝→食管」「病史→病理」，灾难性误伤
- ❌ 单遍同时做精确+模糊：LLM 会在脏上下文上误否
- ❌ 让 35B 自由改写转写文本：只照抄或编造，必须改成是/否判别
- ❌ 用转写语料自建 n-gram 判通顺度：语料本身是脏的，自我强化（历史 32% 准确率）

## 九、与历史结论的关系

`PhoneInbox/docs/asr-accuracy.md`（2026-10-29）是 **whisper.cpp + CPU** 路线的总结，
本次是 **flm NPU** 路线。两者独立验证了同一件事：

> whisper 的 `prompt` 不是热词偏置，参数调优无效，**唯一有效的是拼音层确定性纠错**。

本次在该基础上新增三点：

1. **模糊音归一化**（zh/z、ing/in、ang/an）—— 历史版本用精确拼音，漏掉「套杂→套扎」这类
2. **英文术语正则** —— `Child-Pugh` 被识别成「超的PBG」，拼音匹配完全无能为力
3. **整句对比式判别** —— 比片段式判别的准确率高，能救回相似度 0.93 的长术语

同时确认一个反直觉的事实：**错误更"规整"的引擎更适合接纠错**。
whisper.cpp 单独看更快更准，但它引入的插入/漏字让纠错器失效。
