## 三、人工裁决（本机事实校正，2026-11-23）

### 3.1 真正的口径冲突（同物不同值，需收敛）

| 指标 | 各文件取值 | 裁决 | 依据 |
|---|---|---|---|
| **UMA / carve-out** | 96 GiB（多数）／64 GiB ／48 GiB | **唯一正确值 = 96 GiB** | `rocm-smi` `VRAM Total` = 103079215104 B = 96.00 GiB；`MEMORY.md` §二。64/48 均为报告里的**假设场景**（Strata 折中方案、Gufo 方案讨论），非本机实测，凡引用须带场景前缀 |
| **GTT** | 30.47 ／ 40 ／ 82.79 ／ 97.66 GiB | **唯一正确值 = 30.47 GiB（= host MemTotal）** | 40/82.79/97.66 是「改 BIOS 后 GTT 会变成多大」的推演值 |

### 3.2 假冲突（不同对象共用一个词，无需处理）

| 指标 | 为何看着冲突 |
|---|---|
| `decode t/s` = 12.4 / 29 / 39 / 45.5 / 52 / 90 | 分别是 NPU-4B（12.4）、NPU-flash-2b（29/33）、NPU-lfm2.5（39~45.5）、NPU-hy-mt2（52）、iGPU-35B-Q4_K_P（90）。**对象不同** |
| `memavailable GiB` = 12~18.41 | 是**时变状态量**，每次采样都不同，不是常量 |
| `prefill t/s` = 24.7 / 463 / 580 / 998 | NPU-4B（24.7）／iGPU 100K 冷（463）／iGPU 短（998）。**上下文长度不同** |
| `used / 已用 / size` | 未绑定主语（是 VRAM 还是 RAM、是模型还是 KV），正则抽不出主语属正常 |

### 3.3 结论

- **跨文档逐字复制：0 对**。本库 35 篇报告的文本彼此独立，历史结论没有被复制粘贴散落各处。
- **需要收敛的只有 2 条**（UMA 与 GTT），且 `MEMORY.md` 里已经是正确值，风险在于**旧报告里的假设场景被误读成实测值**。
- 建议：凡在正文引用 64/48 GiB UMA 的旧报告，标注「（假设场景，非本机实测）」。**不做批量改写**——保留原始论证链比统一措辞更重要。
