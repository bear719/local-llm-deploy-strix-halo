# NPU 服务（端口 8219）测试与使用手册

> 实测日期：2026-10-07
> 服务：`flm serve qwen3.5:4b --port 8219`（FastFlowLM / AMD XDNA2 NPU）
> 接口：**OpenAI 兼容** `http://127.0.0.1:8219/v1`

---

## 一、最快验证：一条命令

```bash
curl -s http://127.0.0.1:8219/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3.5:4b","messages":[{"role":"user","content":"你好"}]}'
```

返回 JSON 里有 `choices[0].message.content` 即为正常。

## 二、专用测试脚本（推荐）

路径：`$HOME/WorkBuddy/调试本地模型/tools/test-npu.py`

```bash

$PY test-npu.py              # 全套体检（health + bench）

$PY test-npu.py compare      # NPU vs iGPU(8080) 对比
$PY test-npu.py ask "问题"    # 单次提问 + 细粒度指标
$PY test-npu.py stream "问题" # 流式逐字输出
$PY test-npu.py loadtest 5   # 并发 5 个请求，看排队行为
$PY test-npu.py models       # 列出 FLM 支持的模型
```


**loadtest 3** —— 证实 NPU 是**串行排队**
```
  请求0: 耗时 12.56s | 解码 11.3 t/s
  请求1: 耗时  9.85s | 解码 11.7 t/s
  请求2: 耗时  6.09s | 解码 12.1 t/s

```
耗时呈阶梯递减（12.56 → 9.85 → 6.09）= 三个请求依次执行，**不是并行**。

**compare** —— NPU vs iGPU(8080)
```
NPU  (8219): 总耗时 11.54s | 解码 12.3 t/s
iGPU (8080): 总耗时  4.48s | 解码 n/a(未上报)
```
> iGPU 更快但会吃满显存；NPU 慢但 <2 W 且不占显存。**二者是分工关系，不是替代关系。**
> iGPU 想看到 t/s 需重启 llama-server 时加 `--metrics`。

## 三、FLM 响应里的性能字段（只有 NPU 有）

FLM 在 `usage` 中额外返回原生指标，这是排查性能的关键：

| 字段 | 含义 |
|---|---|
| `prefill_duration_ttft` | 首 token 耗时（秒），即 TTFT |
| `prefill_speed_tps` | prompt 处理速度 t/s |
| `decoding_speed_tps` | 解码速度 t/s ← **核心指标** |
| `kv_token_occupancy_rate_percentage` | KV cache 占用率 % |
| `load_duration` | 模型加载耗时 |
| `decoding_duration` | 解码总时长 |

## 四、接入现有工具

### 4.1 作为 OpenAI 兼容端点接入任意客户端

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8219/v1", api_key="dummy")
r = client.chat.completions.create(
    model="qwen3.5:4b",
    messages=[{"role": "user", "content": "你好"}],
)
print(r.choices[0].message.content)
```

### 4.2 环境变量方式（供各类工具复用）

```bash
export OPENAI_BASE_URL=http://127.0.0.1:8219/v1
export OPENAI_API_KEY=dummy
export OPENAI_MODEL=qwen3.5:4b
```

### 4.3 ⚠️ **FLM 没有内置 Web UI**

已核查：二进制中不存在 `.html`/静态资源，`/opt/fastflowlm` 下无前端文件。
`/v1/models` 返回的是 FLM 全部**可下载模型清单**（37 个），不是"已装模型"——别被列表长度误导。

**想要网页对话界面，需第三方前端指向 8219**，任选其一：

```bash
# 方案 A：Open WebUI（Docker，功能最全）
docker run -d -p 3000:8080 \
  -e OPENAI_API_BASE_URL=http://host.docker.internal:8219/v1 \
  -e OPENAI_API_KEY=dummy \
  -v open-webui:/app/backend/data \
  --add-host=host.docker.internal:host-gateway \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main
# 浏览器开 http://localhost:3000

# 方案 B：LobeChat（Docker）
docker run -d -p 3210:3210 \
  -e OPENAI_API_KEY=dummy \
  -e OPENAI_PROXY_URL=http://host.docker.internal:8219/v1 \
  --add-host=host.docker.internal:host-gateway \
  --name lobe-chat lobehub/lobe-chat
# 浏览器开 http://localhost:3210

# 方案 C：本地起一个（无需 Docker）
# 在 8219 前面挂个静态 chat 页面即可，最简单是自己写个 HTML 用 fetch 调 /v1/chat/completions
```

> ⚠️ **重要：FLM 默认只监听 `127.0.0.1`，Docker 容器连不上！**
> 本机当前**已改为监听 `0.0.0.0`**（已验证局域网 `<主机局域网IP>:8219` 可访问），前端可直接接入：
> ```bash
> flm serve qwen3.5:4b --port 8219 --host 0.0.0.0
> ```
> 若不需要外部访问，去掉 `--host 0.0.0.0` 更安全。

## 五、服务管理

```bash
# 启动（已开放局域网访问，供 Open WebUI 等前端接入）
unset ROCM_PATH HIP_PATH LD_LIBRARY_PATH          # 必须，否则报 No such device
export FLM_MODEL_PATH=$HOME/.config/flm/models
export FLM_DISABLE_UPDATE_CHECK=1
nohup flm serve qwen3.5:4b --port 8219 --host 0.0.0.0 > /tmp/flm-serve.log 2>&1 &

# 停止
kill $(cat /tmp/flm.pid)

# 查状态
ps -o pid,etime,cmd -p $(cat /tmp/flm.pid)
ss -tlnp | grep 8219
tail -f /tmp/flm-serve.log

# 换模型（先 pull）
flm pull qwen3:8b
# 然后重启 serve，把 qwen3.5:4b 换成 qwen3:8b
```

## 六、常见故障对照表

| 症状 | 原因 | 解决 |
|---|---|---|
| `No such device with index '0'` | ROCm 环境变量污染 | 启动前 `unset ROCM_PATH HIP_PATH LD_LIBRARY_PATH` |
| `curl` 返回空、无 HTTP 码 | **连接池被占满**（`NPU busy, request queued (N/10)`） | 重启服务；避免遗留大量未关闭连接 |
| `flm pull` 报 `CURL error: Timeout` | HuggingFace 直连不通 | `export HF_ENDPOINT=https://hf-mirror.com` |
| 模型不被识别 | 目录少了 `models/` 层 | 真路径须为 `$FLM_MODEL_PATH/models/<模型名>/` |
| 日志出现 `NPU busy, request queued` | 正常排队（设备独占，同期 1 个 LLM） | 非故障；需并发请改用 iGPU |
| 端口监听在 `127.0.0.1`，Docker 连不上 | FLM 默认只监听回环 | 启动加 `--host 0.0.0.0` |
| 端口未监听 | 进程已退出 | 查 `/tmp/flm-serve.log` 尾部 |

## 七、关键约束（务必记住）

1. **NPU 单设备独占**：同一时刻只服务 1 个 LLM 请求，其余排队。并发场景请用 iGPU。
2. **不能加速 35B/27B GGUF**：FLM 用 `.q4nx` 私有格式，与 llama.cpp 的 GGUF 不兼容。
3. **12.4 t/s 对 4B 偏低**——换来的是 <2 W 功耗 + 零显存占用 + 与 iGPU 并行。
4. **`/v1/models` 返回全量可下载清单**，不代表已安装。已装用 `flm list --filter installed` 查。
