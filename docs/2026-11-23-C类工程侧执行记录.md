## 三、C3 结构化输出常态化

### 3.1 资产

`tools/schemas/` 六个 schema：`ev_endoscopy`（食管胃静脉曲张内镜记录，含 Sarin/LDRf）、
`lab_panel`、`op_record`、`billing_item`、`discharge_summary`、`study_extract`

`tools/structured.py`：CLI 封装 + 本地字段校验（`required` / `type` / `enum` / `additionalProperties`），
区分 `语法合法` 与 `缺必填`，不让「schema 通过」冒充「内容正确」。

### 3.2 实测（35B-A5_K_P 现行实例，8080）

| 场景 | 耗时 | 输出 tok | 结构合法 | 结果 |
|---|---:|---:|---|---|
| ev_endoscopy（内镜记录） | 3.66s | 202 | 是 | GOV2 / 聚桂醇 20ml / 组织胶 2ml 全对 |
| lab_panel（6 项生化 + 3 项定性） | 7.42s | 358 | 是 | 数值全部为 number 型，定性走枚举 |
| op_record（手术记录） | 4.62s | 154 | 是 | 术式/45min/5ml/张伟+李娜/静脉全麻 全对 |
| op_record（截短文本） | 2.32s | 122 | 是 | 同上 |

### 3.3 三个关键发现（都是踩出来的）

**① `required` + `enum` 会逼模型编造。**
`lab_panel` 最初把 `value_qual`（定性枚举）放进 required，结果定量项（总胆红素 42.6）
的 `value_qual` 被填成「阳性」——模型无法表达"没有"，只能从枚举里瞎选一个。
**移出 required 后立刻正确**：定量项该字段直接缺失，定性项（HBsAg 阴性/便潜血 阳性）正常填。
→ 规则：枚举字段 **绝不 required**；缺失即"无此属性"。

**② 同一字段不能混类型。**
最初 `value` 用 `["number","string","null"]`，模型 100% 选 string，产出 `"42.6"`。
下游做数值比较会错（`"9" > "100"` 为真）。
→ 规则：拆成 `value_num`（number|null）+ `value_qual`（定性枚举），从语法层面断绝混填。

**③ 否定信息抽取不稳定。**
原文「无活动性出血」，`active_bleeding` 第一次填 `null`（应 false）；在 `DEFAULT_INSTR`
加入「否定表述是有效信息」规则后修好。
但「无并发症」→ `complications` 三次里两次仍是 `null`（schema 已写明"填该表述"）。
→ 结论：**否定/布尔字段必须人工核对**，不能凭 schema 通过就放行。

### 3.4 边界（写进工具注释）

schema 只保证**结构**，不保证**内容**。字段填错值仍会发生。
所以校验结果区分 `语法合法` 与 `缺必填`，且 `structured.py` 从不宣称"准确"。

## 四、踩坑（新增）

### 4.1 grammar 退化：0.33 t/s 且 slot 不释放

一次 `op_record` 调用跑满 240s 未完成。事后取证：

```
llamacpp:tokens_predicted_total 232838 → 232840（6 秒 2 token = 0.33 t/s，正常 76）
/slots  is_processing = True
POST /slots/0?action=erase|cancel|reset|release  → 全部 501 Not Implemented
kill -TERM（面板 autoRestart 常规手段） → 进程卡在 shutdown 22s 不退出、health 转 down
kill -9 → 30s 后新进程加载完成恢复正常
```

复跑同一请求 4.62s 正常，**不可复现** → 定性为偶发退化。
但「客户端超时后服务端不释放 slot」是确定的：一个卡死请求会占死唯一槽位。

处置口径：
1. 结构化调用必须自带 `--max-tokens` 上限（本次 2048 仍失控，说明上限不解决退化本身）；
2. 发现 `is_processing=True` 且 `tokens_predicted` 增速 < 5/s → 直接 `kill -TERM`，10s 不退则 `kill -9`；
3. 该 fork 的 slot 路由**不支持任何取消 action**，别在 `?action=` 上浪费试错。

### 4.2 BM25 缓存路径反推 → 必崩

`cache_path.rsplit(".pkl",1)[0]` 对 `all.json.bm25.pkl` 得到 `all.json.bm25`，文件不存在，
`os.path.getmtime` 抛 `FileNotFoundError`。第一次跑不崩（缓存不存在跳过检查），
第二次必崩——典型的"只测了一次"事故。修法：把索引路径与缓存路径分开传。

### 4.3 `--source` 过滤必须禁用 BM25 缓存

过滤后 chunk 下标重排，缓存里的 posting 索引全部错位。已强制 `--source` 时不读不写缓存。

### 4.4 索引速度按 1431 块估 368s，实际卡在队列

期间单条 embed 测速得 14.39s —— 不是 NPU 变慢，是**测速请求排在 1431 段后面**
（NPU 严格串行 `NPU Locked!`）。任何"顺手测一下 NPU"的动作在索引期间都会误判。
