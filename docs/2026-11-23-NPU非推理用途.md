# 2026-11-23-NPU 非推理用途（补充调研）

> 承接 `2026-11-23-NPU充分利用方案.md`。本文只回答一个问题：**除了跑 LLM，这颗 XDNA2 还能干什么**。
> 所有"可做/不可做"结论均以本机实测或已核实的官方文档为依据；未实测项标 `[待实测]`。

---

## 0. 先说清楚"非推理"到底有哪几类

把 NPU 用途按**是否运行神经网络**切两刀，一共四个格子：

| | 跑神经网络 | 不跑神经网络 |
|---|---|---|
| **走 flm（现成）** | embedding / ASR / 视觉 VLM / d3 决策 | `flm validate`（栈自检） |
| **走 XRT（需自研）** | 自定义 ONNX / PyTorch 模型 | 纯算子加速（矩阵、卷积、FFT） |

**结论先行**：
- **左上格是唯一值得干的**（embedding 是核心，VLM 可作为可选补充）。
- **左上格之外的格子，本机都不划算**——XRT 开发头缺失，且带宽天花板决定自研算子永远慢于 iGPU。
- 真正被忽略的"非推理"价值在于**工程属性**：它不占 VRAM、不抢 GPU 主 slot、功耗 <2 W、可 7×24 常驻。这些属性支撑了四类平台级用法（向量检索底座、去重聚类、门控与降级、指标与自检）。

## 1. 本机实测：能做的"非 LLM"推理

### 1.1 Embedding —— 唯一的三星级用途

| 项 | 实测（2026-11-23） |
|---|---|
| 单条 13 字 | 0.171 s |
| 长文 234 / 1134 / 2268 / 4518 汉字 | 0.223 / 0.471 / 0.796 / 0.822 s |
| 6 条批 | 1.60 s（3.8 条/s） |
| 维度 | 768，全非零，L2≈0.997 |
| 语义检索 | Top-1 4/4 命中 |

**★ 新发现的长度特性**（原方案未覆盖）：
- **不报错、不截断**：4518 汉字仍返回单条 768 维向量，耗时 0.822 s。
- 但**语义被稀释**：查询「食管静脉曲张破裂出血的处理」与含该关键词的长文（43→1252 字）余弦相似度从 **0.604 → 0.545**，单调下降但平缓。
- → **分块是必要的，但分块粒度可以用到 1000~2000 字**，比原方案建议的 512 字更宽松，能省一半向量量。建议：**800 字 / 重叠 100 字**。

### 1.2 短文本相似度 —— 去重/聚类的可用底座

实测 10 条 15~20 字文本，逐对余弦：

| 对 | cos |
|---|---:|
| `患者呕血黑便3天` ~ `患者呕血黑便三天` | **0.983** |
| `患者呕血黑便3天` ~ `患者呕血、黑便3天` | **0.978** |
| `予奥美拉唑40mg` ~ `予奥美拉唑 40mg` | **0.994** |
| `予奥美拉唑40mg` ~ `予奥美拉唑40毫克` | **0.984** |
| `患者呕血黑便3天` ~ `今日体温正常` | **0.308** |
| `患者呕血黑便3天` ~ `患者因呕血黑便3天入院` | 0.931 |

→ **近重复 0.93~0.99，无关 0.31，中间地带极干净**。阈值 0.95 零误伤，0.90 可抓同义扩张。
单条 183 ms ⇒ **1000 段病历去重约 3 分钟**，比 CPU 上的 minhash/SimHash（还要调参、还怕语序）稳定得多。

已交付：`tools/npu-dedup.py`（每行一条，输出 `.dedup` / `--cluster` / `--json`）。

### 1.3 ASR —— 已上线，定位受限

CER 4.11%（拼音确定性纠错后），3.3~5.4× 实时。**只做会议/讲座/口述草稿，不进正式病历。**

### 1.4 视觉 VLM —— 可选，但需先下 4 GB

| 项 | 值 |
|---|---|
| 模型 | `qwen3vl-it:4b` / `qwen3vl-flash:4b`，各 4.0 GB；`qwen2.5vl-it:3b` 3.0 GB |
| 本机现状 | **未安装**，模型目录为空壳；调用返回 `Failed to load qwen3vl-it:4b model!`（500） |
| 官方媒体预算 | `qwen3vl-flash:4b` 图片长边压到 **256 px**（flash 档 OCR 不可用）；`qwen3vl-it:4b`（非 flash）预算更宽 `[待实测]` |

**OCR 的真实替代方案**：本机已装 `rapidocr-onnxruntime`（CPU），预热后 **259 ms/张**，文字准确（`Child-Pugh score B EVL performed` / `Omeprazole 40mg IVq12h` 全对）。
→ **OCR 不要上 NPU**。VLM 的合理用途是「整页版面理解」（表格结构、图注与正文对应），不是逐字识别。**收益不足 4 GB 下载 + 换模停机**，非刚需不建议装。

### 1.5 d3 决策模型 —— 架构决定它只能做"选动作"

`d3:edge`（596 MB，已下载未启用）= Qwen3.5-0.8B 编码器 + 255 类动作码 readout，`POST /v1/systemone` 返概率、不生成文本。
- 能做的：**基于 prompt 词面的工具/后端选择**（route）。
- 不能做的：难度判定、质量评估、内容纠错（均需判断力，已否决）。
- 接入成本：docproxy 现有分流只认 `/v1/chat/completions|/v1/*`，`/v1/systemone` **需新增路由分支**（约 30 行）。且 NPU 全局串行，高并发会把 embed/ASR 挤到 12.7 s。

## 2. 不能做（或不该做）的"非推理"

| 想法 | 判定 | 硬依据 |
|---|---|---|
| **OCR 加速** | ❌ | rapidocr CPU 已 259 ms/张；视觉模型需 4 GB 且 flash 档 256 px 截断 |
| **TTS / 语音合成** | ❌ | flm 无 TTS；现用 Breeze-TTS-2（Vulkan）已够。自研需 xclbin |
| **图像处理（滤镜/超分/抠图）** | ❌ | 无对应 flm 模型；VLM 不做像素输出 |
| **通用矩阵/FFT 加速库** | ❌ | 需 XRT dev + xclbin 编译；带宽 57~141 GB/s < iGPU 209.9，注定更慢 |
| **密码学 / 密钥运算** | ❌ | NPU 不是安全域，无 TEE 语义 |
| **网络包处理 / 卸载** | ❌ | PCIe 16 GT/s ×16 但无 DMA 卸载框架；CPU 32 线程远超需求 |
| **挖矿 / 算力出租** | ❌ | 无 XDNA2 通用算力生态 |
| **视频编解码加速** | ❌ | 本机 VCN 在 iGPU 侧（`/dev/dri`），NPU 无编解码单元 |

### 2.1 自研 NPU 算子的真实门槛（核查结果）

| 需求 | 本机状态 |
|---|---|
| XRT 运行时库 | ✅ `libxrt2 / libxrt-npu2 2.21.75`（`libxrt_core.so.2`、`libxrt_driver_xdna.so.2` 齐全） |
| XRT 开发头 | ❌ `/usr/include/xrt` **不存在**，`/opt/xilinx` 不存在 |
| 命令行工具 | ❌ `xrt-smi` / `xbutil` / `xclbinutil` 全无 |
| 现成 xclbin | ✅ `/opt/fastflowlm/share/flm/xclbins/<模型>/*.xclbin`（`mm` / `mv` / `attn_full_mask` / `sliding_attn`，56 个模型目录） |
| 驱动可调参数 | `aie2_max_col` / `force_cmdlist` / `force_iova`（均为空 = 默认） |

→ 自研路径 = 装 `xrt-dev` → 装 Vitis AI / IRON / mlir-aie → 自写 kernel 编 xclbin → 自写 host 代码。**即便跑通，57~141 GB/s 的带宽上限决定了任何大算子都慢于 iGPU 的 209.9 GB/s**。
**明确不推荐**，除非出现「flm 完全没有、且必须 <2 W 常驻」的刚需。

## 3. 真正被忽略的用法：把 NPU 当"工程属性"而非"算力"

这一节是本文的核心。NPU 的价值不在 t/s，在**它不消耗的三样东西**：

| 不消耗 | 对比 | 可换来的能力 |
|---|---|---|
| **VRAM（96 GiB carve-out）** | 35B 主模型占 33.4 GiB | 主模型可维持 256K ctx + cache-ram 16384 不被挤压 |
| **GPU 主 slot（`-np 1`）LCP 前缀** | 冷启动 149 s → 复用 <1 s | 杂活不再冲掉用户的会话前缀 |
| **功耗（<2 W）** | iGPU 满载 120 W 撞功耗墙 | 可 7×24 常驻，不参与功耗预算竞争 |

由此派生四类平台级用法：

### 3.1 ⭐⭐⭐ 向量检索底座（RAG 的地基）

这是 embedding 的真正用途，不是"跑个模型看看"。

- 数据源：`~/WorkBuddy/调试本地模型/*.md`（70+ 篇实验报告）、医学指南、病案、代码库。
- 粒度：**800 字 / 重叠 100 字**（依据 §1.1 长度实验）。
- 规模：1000 页 ≈ 4000 块 ≈ **17.5 分钟**；10 万块 ≈ 7.3 小时（夜间两晚）。
- 检索：`npu-sidecar.py search` 已可用；再叠加 35B 做生成 = 完整 RAG。
- **与关键词检索的本质差异**：`grep` 找「呕血」，向量能找「消化道出血」「黑便」，这是病历/文献检索真正的痛点。

### 3.2 ⭐⭐⭐ 数据质量流水线（去重 / 聚类 / 异常发现）

- **去重**：`npu-dedup.py`，阈值 0.95（近重复）/ 0.90（同义）。
  真实用途：① 病案模板句识别（大量重复的「今日体温正常」可折叠）；② 管线输出查重（多 agent 重复产出）；③ 语料清洗。
- **聚类**：`--cluster` 输出簇，可用于「本周投诉归类」「实验报告主题地图」。
- **异常发现**：对同类文本算质心，cos 最低的 5% 即为离群项 → 病历书写模板偏移预警。`[待实测]`

### 3.3 ⭐⭐ 门控与降级（可用性工程）

- `npu-idle-gate.py`：读 8080 `/slots` 的 `is_processing` + `MemAvailable`，连续空闲 N 秒才放行批处理。**这是"NPU 满载会让 GPU decode 掉 12.7%"的直接对策**。
- **降级链**：8219 挂了 → docproxy 显式 502/503（不静默回落），调用方按需切 35B。NPU 在这里的角色是「廉价兜底」而非「主力」。
- **反例**：不要用 NPU 做健康检查的"必须项"，它串行且随机排队。

### 3.4 ⭐ 指标与自检（可观测性）

| 项 | 手段 | 已验证 |
|---|---|---|
| NPU 栈健康 | `flm validate -j` → `ready:true / aie2p / 8 cols / fw 1.1.2.65 / memlock infinity / kernel 7.0.0-43` | ✅ 本日实测 |
| 功耗状态 | `/sys/class/accel/accel0/device/power_state`（`D0`/`D3hot`）、`power/runtime_status` | ✅ |
| 链路 | `current_link_speed 16.0 GT/s`，`current_link_width 16` | ✅ |
| FW | `/sys/class/accel/accel0/device/fw_version` = `1.1.2.65` | ✅ |
| 首 token / 解码速度 | flm 在 `usage` 里原生返回 `prefill_duration_ttft` / `decoding_speed_tps` / `kv_token_occupancy_rate_percentage` | ✅ |
| 温度 / 功耗（W） | ❌ **无 hwmon 节点**，需 `xrt-smi`（未装） | ❌ |

→ 可以做一个 30 行脚本把 `flm validate` + sysfs 打包成 prometheus 文本格式，纳入现有监控。`[待实测]`

## 4. 决策表：什么活给 NPU

| 任务特征 | 归谁 | 理由 |
|---|---|---|
| 需要判断力（judge / 纠错 / 质量评估） | **GPU 35B** | NPU 小模型判断力不足（已实测否决） |
| 需要长生成（>200 token） | **GPU 35B** | NPU decode 52 t/s 且串行 |
| 需要并发 | **GPU 35B** | NPU 全局串行，第二个请求排队 |
| 大批量、短输出、可延迟 | **NPU** ✅ | 免费、常驻、不占 VRAM |
| 需要低功耗常驻（7×24） | **NPU** ✅ | <2 W vs iGPU 120 W |
| 需要结构化 JSON 且 schema 明确 | **NPU** ✅ | xgrammar 强制格式，0.5~0.9 s |
| 翻译（中英） | **NPU** ✅ | 比 35B 快 23.7×，质量持平 |
| OCR | **CPU rapidocr** | 259 ms/张，无需 4 GB 模型 |
| 像素级图像生成/处理 | **iGPU（sd.cpp）** | NPU 无此能力 |
